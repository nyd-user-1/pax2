# UX audit, 2026-10-19

Every route and the shell read in full against docs/SPEC.md, including d44b19b's /loop and /flow. Verdicts first, the target sitemap second, the punch list last. Recommendations only; nothing here has been changed.

## The structural problems — two live, one ruled intentional

**1. The app serves two audiences on one nav and admits it out loud.** The sidebar's four real items (Home, Chat, Dashboard, Channels) sit above eighteen items labeled "Work in progress" — a label a newly onboarded creator reads as "most of this product is unfinished," when the spec marks Recording, Scoring, Publishing and Scripts as Built. Meanwhile genuinely internal surfaces (Pipeline, Build, Project Management, ML, Evals, Endgame, Loop) sit in the same list as the product, in internal vocabulary ("iWAR", "Evals", "Feature lift", "Endgame"). The fix is not reordering; it is splitting the nav by audience: a creator surface, a research surface, and an admin surface gated on `user.admin`.

**2. One video's journey is scattered across sibling pages instead of being a workflow.** A video moves draft → scored → published, but the app renders that as three separate sidebar destinations (`/drafts`, `/scoring`, `/publishing`) that are literally the same component — `OriginalsQueue` with a different `queue` prop — plus a fourth page (`/v/[id]`) for the video itself. Three nav entries for one pipeline, and no page shows the pipeline.

**3. The front door — ruled intentional, 2026-10-19.** `/` re-exports `/record/page` (the marketing landing) and the flow starts at `/recording`. The ruling: the landing is a honey trap by design — a visitor begins creating a video immediately and meets sign-in only at the point of saving (the Studio already takes a bare email when signed out). The funnel stands; no change recommended. What remains is developer-facing only — the flow's steps live under `/record/*` while its entry is `/recording` — a naming wrinkle to absorb, not fix.

(admin or      Evidence (/feature-lift + /patterns)

That takes the sidebar from 28 destinations to about 12 for a creator, and the "Work in progress" label disappears — shipped features stop apologizing for themselves.

## The missing workflow: My videos

The merge of the three queues should not be three tabs bolted on. The page one owner needs is their videos as a pipeline: each video a row or card showing where it stands (draft, scored with the number, approved, published, tracking), with the next action inline — score it, read the findings, approve, publish, see the curve. Everything to build it exists: `OriginalsQueue` has the rows, `/v/[id]` has the actions, the ledger has the events. Today the user plays the pipeline in their head across four pages; the app should draw it once. The new `/flow` page is the clearest witness: its step cards each name and link the page that runs that step, a hand-drawn wayfinding map for a pipeline no page renders live.

## Design retouches on the keepers

- **Two page-finders in one header.** `HeaderSearch` (⌘K) and `PageSwitcher` (the title pill) open the same list of the same pages, side by side. Keep ⌘K search; make the title a plain title.
- **Mobile loses the app.** The mobile header renders only the four NAV items plus Record; search and the switcher are desktop-only. On a phone, 22 pages are reachable only by typing a URL. The consolidated nav (12 items) fits a mobile sheet; today's 27 never will — one more reason to consolidate.
- **Dashboard mixes real, sample, and admin.** One `demo` flag swaps whole sections to SAMPLE_* numbers, a second (`readersDemo`) swaps the Readers block independently, and poller/pipeline controls sit above partner-facing stats. Split it: an admin ops row (controls, poller, queue), and a stats body that shows real numbers or an honest empty state — the two-badge sample system reads as real at a glance, which is the one thing a dashboard must never do.
- **Teach a Model violates the block rule.** `/labeling`'s course cards and the classifier's chapter layout are bare `article`/`div` surfaces (`rounded-2xl border bg-card`), not MainBlock-family blocks, and both pages render their own `<h1>` under a shell header that already names the page. Same double-title on `/labeling/classifier`.
- **`/library` opens with a lead-in paragraph** under the header describing what the page is — the standing rule says delete these; the browser below carries it.
- **Naming drift: iWAR vs. outliers.** The route is `/outliers`, the reader-facing rename to "outlier" is done, but the sidebar and title still say "iWAR". One name everywhere.
- **Hand-rolled tables.** `/outliers`, `/live-tracking` and `/pipeline` each write their own `<table>` markup with near-identical header styling inside `TableBlock`. One shared table pattern (the nova Table that `/glossary` and `/build` already use) ends the drift.
- **The announcement banner is hardcoded** (`BANNER_KEY = "pax2:banner:elevenlabs-voices"` in shell.tsx). Fine for now; it will go stale silently. Move the text and key to one constant file so shipping a new banner is a one-line change, or drop the banner between ships.
- **StepBar never advances** (every flow step passes `step={1}`). Either wire the steps or remove the numbers.

## Punch list, by impact

1. **Merge the queue trio into My videos** (one page, pipeline view). Largest UX gain; smallest risk — one component already renders all three.
2. **Sidebar restructure**: creator/research/admin groups, admin gated, "Work in progress" label gone, iWAR renamed. Pure nav-array edits in shell.tsx.
3. **`/chat` folds into `/app/home`** (redirect). One component, one nav entry.
4. **Tracking merge**: Live · Settled · Curves as one page; `/velocity-tracker` and `/live-tracking` redirect in.
5. **Retire `/endgame`** into `/channels`' empty state.
6. **Evidence merge**: `/feature-lift` + `/patterns`.
7. **Dashboard split**: admin ops vs. honest stats; one sample-data policy.
8. **Retouches**: Teach a Model onto blocks, double h1s removed, library lead-in removed, one page-finder, shared table pattern, StepBar wired.
9. **Decide `/tags`**: into the research nav or deleted.

Items 1 to 3 change what the product feels like for the client kickoff; 4 to 7 pay down the research sprawl; 8 and 9 are an afternoon of sweeping.
