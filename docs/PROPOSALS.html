PAX

eR

The standing definition, which the five below redefine: three rates per paid run — stop, watch, act — each against a frozen reference average.

R = 0.25·Engage + 0.40·Interest + 0.35·Act 50 = the reference average Engage = threeSecondPlays ÷ impressions Interest = averageViewDuration ÷ videoLength Act = (shares + saves + comments) ÷ threeSecondPlays each rate → evidence-weighted: (count + k·ref) ÷ (base + k) each rate → component score: percentile of distance from reference, log-odds scale, 0–100
Inputs
Analytics API, Data API
Rewards
Stopping the scroll, holding the watch, prompting an action — against the first round’s pooled average
State
Defined, unscored: no real video carries an eR; impressions, shares, and saves exist only for paid delivery
Limit
Within-run only — nothing is normalized to the channel, so eR cannot compare across channels the way the proposals can
Reads as
50 = the reference average; the full definition lives on the Resonance tab

pR

Built from public data alone: the audience’s disproportionate response, read from what YouTube shows everyone.

R = 100 · Φ( 0.50·z(outlierScore) + 0.30·z(engagementRate) + 0.20·z(durability) ) outlierScore = views ÷ channel median (within-channel, log scale) engagementRate = (likes + comments) ÷ views (vs the channel’s own typical rate) durability = days the poller saw velocity above threshold (vs the channel’s typical life)
Inputs
Data API, Poller, Catalog
Rewards
Beating your own channel’s usual on reach, depth, and staying power
z(·)
Within-channel standard score, evidence-weighted toward 0 under ~2,000 views
Limit
No watch behavior exists publicly; outlierScore carries that load as a proxy
Reads as
50 = the channel’s usual; one spread above ≈ 84

hR

Everything in hand, nothing invented: what happened, weighted 70, against what it resembles, weighted 30.

R = 100 · Φ( 0.70·OUTCOME + 0.30·CONTEXT ) OUTCOME = 0.5·z(outlierScore) + 0.3·z(engagementRate) + 0.2·z(earlyShareOfViews) CONTEXT = 0.6·z(neighborhoodLift) + 0.4·z(hitProbability) paid rows add: OUTCOME += z(completion_rate_reported_pct), weights renormalized
Inputs
Data API, Poller, Catalog, Embeddings, Models, CSV where present
Rewards
Measured performance first; content that sits in historically lifting neighborhoods second
Rule
Every component already exists on a tab; this proposal only combines
Limit
hitProbability is a forecast inside a score of outcomes — held to 12% of the total for that reason
Reads as
50 = expected for this channel and this content neighborhood

xR

Derivations of derivations: each video becomes a fitted curve and a feature vector, scored by its projection onto the axis that historically separates winners.

1. Fit the poller series: V(t) = V∞ · (1 − e^(−t/τ)) → V∞ (ceiling), τ (time constant) 2. Engagement elasticity: ε = d(log likes) ÷ d(log views) across the series 3. Standardize the vector: x = [log(V∞/median), τ, ε, fit residual, transcriptPace, hookWordCount, firstCutTime, textOnScreen, neighborhoodLift, …] → z within channel 4. Performance axis: w = the discriminant axis separating ≥3x from <3x on the settled corpus 5. R = 100 · Φ( x · w ) the video’s projection on that axis, as a percentile
Inputs
Poller (the curve), Catalog, Transcripts, Composition, Embeddings
New derivations
τ and V∞ from the curve fit; ε, an elasticity; w, the fitted axis
Rewards
The shape of success — fast time constants, compounding approval, a winning craft profile — not just its size
Limit
The axis is refit on each corpus rebuild; scores compare only within one fit, so w is versioned like a model
Reads as
50 = on the fence between the two populations

fR

Forget the metric list. Resonance is disproportionate response: how much more an audience gives a video than that audience gives everything else, per unit of exposure.

R = 100 · Φ( log [ ∫ response(t) dt ÷ ∫ expected_response(t) dt ] ) response = attention-seconds + weighted actions, as observed expected_response = the same audience’s baseline curve for this channel, length and placement exposure = whatever pushed it — impressions, paid starts, algorithmic serves — the denominator, never the credit
Thesis
50 means the audience responded exactly as it responds to everything; resonance is the measured surplus
Property
Platform-agnostic: defined on curves and ratios, not on any vendor’s named counts
Property
Separates push from pull — exposure bought can never masquerade as response earned
Limit
Needs a response curve per audience, the hardest data to hold; every practical version above approximates this one
Reads as
The definition the other four converge toward

mR

From physics: a driven system responds enormously at its natural modes, and different modes produce different — but each perfectly regular — patterns. Outperformers are videos that hit a mode.

1. Template: normalize every video onto the same fixed axes (craft, trajectory, neighborhood, engagement profile), each axis a within-channel percentile → one regular polygon per video 2. Modes: cluster the templates of settled ≥3x videos → K recurring winning configurations (sometimes abcdef, sometimes ghijkl — each mode is one bundle of threads) 3. Score: R = 100 · max_k [ similarity(template, mode_k) · lift_k ÷ max lift ] similarity = cosine on the normalized axes; lift_k = the mode’s measured share-over-3x
The physics
MRI is the proof of concept: chaotic, unique bodies, excited along one shared property, collapse into a single symmetric diagnostic image. The template is that image; the modes are the resonant patterns
Inputs
Catalog, Poller, Transcripts, Composition, Embeddings — all in hand; the house already draws one deterministic signature per video (viometric frequency)
Rewards
Proximity to any known winning configuration, not to one averaged archetype — videos with different trait-bundles can score equally high
Common denominators
Axes high across every mode are the minimums; axes high in only some modes are the interchangeable threads
Limit
Modes are discovered, so K and the clustering are pre-registered and versioned; a mode can exist that the corpus has not seen yet
Reads as
100 = squarely on a known mode; 50 = between modes; low = off every pattern that has worked here
